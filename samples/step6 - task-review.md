## 主要问题（Agent 分批视角）

```plain
当前编号顺序风险:

  1.1 建新表 ──► 1.2 删旧 UDP ──► ... ──► 5.x 改业务
       ✅              ❌ 过早              ❌ 旧路径已无

正确切点应是:

  Foundation → Infra → Business(切流) → Cleanup(删旧)
```

1. **`1.2` 放在 Foundation = 致命排序错误**  
   应在全部写路径切到 Grant/Checker 之后再删。

2. **§3 与 §6 职责重叠**  
   AuthManagement grants、公司校验、OpenAPI 拒 `directoryIds` 被拆成两段，Agent 易双改同一文件。

3. **`5.1` / `5.6` 粒度过粗**  
   不适合单 Agent 一批；应按模块或写路径拆分。

4. **测试与实现耦合在同一编号段**  
   可接受串行；若要并行，实现任务与测试任务需拆开并声明依赖。

5. **与 design Migration Plan 不一致**  
   Design：`建新表 → 删旧表 → 发 server → 发 website`  
   Tasks：删旧表夹在骨架阶段，且 website/server 交叉任务无阶段门禁。
