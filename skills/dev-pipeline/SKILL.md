# Dev Pipeline（历史正文）

你是**调度者**。只做：派发、读结论、判定、推进。不亲自探索、设计、写代码、跑测试（读配置与 git 基线除外）。

本文件只定义协议与硬约束，不规定流程。流程由「流水线」定义，角色由「角色注册表」登记。

```
dev-pipeline/
├── SKILL.md       协议（本文件）
├── roles.md       角色注册表：读它确定可用角色、权限类、产物名
├── authoring.md   新增角色 / 编写流水线时读
├── agents/        角色文件 pipeline-*.md
└── pipelines/     dev.md · design-review.md · impl-verify.md
```



## 选用

按序判断，取第一个命中：

1. 用户指名流水线 → 读 `pipelines/<id>.md`，严格按其执行。
2. 用户点名一个角色，或只需一次独立工作 → **单点**。
3. 用户点名多个角色或描述了协作顺序，且无对应流水线 → **临时组合**。
4. 用户未点名，但请求符合某流水线「触发」→ 读该文件，按其"直接使用 / 先问再用"处理。
5. 其余 → 不使用，直接做。

| id | 做什么 | 选它的情形 |
|---|---|---|
| `dev` | 探索 → 设计 + 审核 → 用户确认 → 实施 + 验证 | 无设计、要实施：跨模块功能、重构、公共接口变更 |
| `design-review` | 设计 → 独立评审 → 修订 | 只要设计 / 方案并过审；评审一份已有设计；不实施 |
| `impl-verify` | 实施 → 独立验证 → 修复 | 已有确认的设计，要实施并验证 |

`dev` = 探索 + `design-review` + 确认门 + `impl-verify`。两个短流水线可依次接力。

- **单点**：建任务目录，`00-task.md` 只写「目标」；填派发块，派发，读返回，汇报。
- **临时组合**：按依赖决定顺序，前步产物作后步输入，每步按单点处理。**不自动循环**：某步返回需回改的结论（`REVISE` / `FAIL` / `BLOCKED` / `ISSUE`）→ 汇报并给下一步建议，等用户决定；用户同意的单次回改按单点派发。要自动循环，用或新增流水线。



## 任务目录与记录

首次派发前建 `.pipeline/<yyyymmdd>-<slug>/`，提示用户将 `.pipeline/` 加入 `.gitignore`。目录内：

- `00-task.md`：任务简报。必填「目标」；其余按所用角色 / 流水线的「前置」填写：约束、可验证的验收标准、验证命令、基线、验证环境、开关状态（含并发数）、角色映射、流水线名。
- `decisions.md`：已确认决策清单。建目录时创建（空）。仅调度者写，仅追加，一条一行：`- [阶段/轮次] 决定 — 原因`。推翻旧决定时追加新行并注明"取代 <原条目>"。
- `run.log`：派发日志。仅调度者写；每个实例返回后追加一行：`<序号> <流水线:阶段 | 单点 | 临时> <角色>[/<模式>] → <输出文件> | <返回>`。
- 角色产物：文件名见 `roles.md`「产物」列。

`decisions.md` 仅在以下时机追加：

1. 用户提出新约束、修改验收标准，或对分歧作出裁决。
2. 用户在检查点的修订意见要点、手改要点。
3. 用户对角色选择、未解问题的答复。
4. 实施 `BLOCKED` 回设计时，查明的类型与事实（如"接口 X 不支持 Y"）。

不记录过程、推测、子智能体的意见。

开关状态记入 `00-task.md`；中途开启或关闭：更新记录，下一个检查点生效。开关值可在请求中（优先）或 AGENTS.md 中指定，如「dev-pipeline 并发数：2」。



## 派发块

每次派发的 prompt 只传以下项，不复述文件内容，不附带推理或偏好：

- 任务目录
- 角色 / agent；模式（修订 / 复核 / 并发 / 集成 / 修复 / 续做；无则不写）
- 输入文件（含 `00-task.md`、`decisions.md`）
- 输出文件
- 轮次（如有）；并发时另传步骤编号与文件白名单
- 追加约束（可选）



## 硬约束

1. **独立性**：`roles.md`「独立于」所列的角色，只读文件，不接收被独立方的推理或自检结论；派发只传路径。
2. **写入**：角色只写自己的输出文件；只有「改源码」类可改源码。并发的实例不写同一文件；调度者不合并产物。
3. **git / 依赖**：角色不得执行改变工作区状态的 git 命令（`commit` / `push` / `stash` / `checkout` / `reset` / `clean`）；任务明确要求 commit 时，仅「改源码」类可 commit。不得安装依赖。
4. **不嵌套**：子智能体不得派生子智能体。
5. **追加约束只收紧**：派发块的追加约束不得放宽角色文件的规则。
6. **读返回**：返回只含角色文件「返回」节规定的内容。调度者只读返回值和产物首行 verdict。仅在以下情形读产物对应节：`FAIL`（失败项、环境阻塞）、`BLOCKED`（偏离）、`ISSUE` / `MINOR`（复核节）、未解问题数 >0（探索报告或设计文档的「未解问题」节）、"不可行"数 >0 或连续两轮"不接受"数 >0（评审回应与对应评审记录）、检查点需要摘要（设计文档）。
7. **失败**：子智能体失败或返回不合规 → 重派一次并指出问题；仍失败则汇报用户，不代做。限流 / 过载类错误例外：不计入重派次数；并发数降为当前的一半（最低 1）并记入 `00-task.md`，重派失败项，告知用户。
8. **提问合并**：需要问用户的问题合并为一次提问。



## 角色解析

对所用的每个角色，按序取第一个可用项：

1. **用户指定**：请求或 AGENTS.md 点名了该角色用哪个 agent。
2. **用户预设**：已注册 agent 的 description 含 `pipeline-role: <角色>`。无该标记的 agent 不自动匹配。
3. **自带**：`roles.md` 登记的 agent 文件（去掉 `.md`）已注册 → 用其 `subagent_type`。选中后做**副本校验**：若能在子智能体定义目录（如 `~/.zcode/agents/`、项目内 `.zcode/agents/`）定位到同名文件，与本 skill `agents/` 下的源文件 diff——仅 frontmatter 差异 → 忽略；正文不一致 → 停止，提示用户以源文件正文更新注册副本后再继续；定位不到 → 跳过校验。
4. **兜底**：general-purpose 子智能体；prompt 开头写"先读取 `<绝对路径>/agents/<agent 文件>` 并严格遵守"。结束时提示用户把 `agents/*.md` 复制到当前 AGENT 工具的子智能体定义目录。

第 1、2 条的附加规则：

- **工具检查**：「改源码」类必须带 Edit；「只写产物」类不得带 Edit。第 2 条不符 → 跳过并告知用户；第 1 条不符 → 询问是否仍使用。
- **不兼任**：同一任务中，`roles.md` 中互为「独立于」的两个角色不得由同一 agent 担任。冲突时，登记了「独立于」的角色跳过该 agent，继续解析下一项，并告知用户。
- **多个标记**：同一角色有多个带标记的 agent → 询问（所有待定角色合并为一次，列候选并给推荐）。

选中第 1、2 条的 agent 时，派发 prompt 追加协议补丁（`<角色文件>` 为本 skill `agents/` 下该文件的绝对路径）：

"另读 `<角色文件>` 的「规则」「输出文件结构」「返回」，以及与当前模式对应的小节，并遵守。做法以你自身指令为准；文件路径、首行 verdict、返回内容、`decisions.md` 只读、写入边界以该文件为准。"

映射写入 `00-task.md` 后，后续轮次沿用，不重新匹配。



## 并发

**方式**：同一条消息里发出多个子智能体调用 = 并发；分多条消息 = 串行。整批返回后才进入下一步。

**上限**：每批个数 ≤ 并发数（默认 3；用户说"并发 N / 最多 N 个并发"，N ≥1，1 即全串行；用户指定优先，含中途修改）。待派个数超过上限时分波：波内并发，波间串行，一波全部返回后再派下一波。

**条件**：并发的实例互不依赖，输出文件各异。

- 「只写产物」类：调度者划分互不重叠的范围（目录 / 模块）；拿不准则只派一个。
- 「改源码」类（全部满足才并发，否则串行）：各实例有**文件白名单**且两两不相交；不依赖对方产出；不含共享或生成文件（barrel / index、路由注册、i18n 汇总、lockfile、全局类型声明），这些放进并行组之后的串行"集成步骤"。

**失败处理**：整批返回后处理。任一 `BLOCKED` → 不再派后续波，已完成的改动保留，按流水线规定处理。

哪些阶段可并发由流水线规定；临时组合中仅限同角色、范围不重叠的批次。



## 必须停下询问用户

任何开关下都要停下：轮次耗尽（汇报分歧与产物路径，不得自行放宽标准）、验收标准需修改、需要破坏性操作（删除数据、改配置、改依赖）、人工意见被标"不可行"、`BLOCKED(需确认)`。各流水线另有补充。



## 结束

汇报（≤15 行）：产物目录、各角色关键 verdict、`UNVERIFIED` / 需人工项、遗留问题；流水线可补充内容。用过兜底角色时附复制 `agents/*.md` 的提示。



## 恢复

会话中断后用户要求继续：读 `00-task.md`（流水线名、开关）、`run.log` 末行和产物首行 verdict，推断所处阶段，向用户一句话确认后继续。无 `run.log` 时按文件存在与首行 verdict 推断。不另建状态文件。
